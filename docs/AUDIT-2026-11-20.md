## Stage A: make it usable (blockers)

### AUDIT-01: Over any web page, the Helm and the notch are blank. Severity: critical. Confirmed live
- **What happens:**
  - With a web page shown, the Helm is an empty dark pill: no back or forward, no address, no assistant.
  - The notch is an empty dark box: no Shields and no minimise, maximise or close buttons.
  - So on a normal page you can't see the address, can't use the window buttons, and can't drag the window.
  - Input still reaches the hidden UI: clicking where the address field is and typing `example.com` + Enter navigated the tab.
  - The new-tab page and `odyssey://` pages (no page window) render fine.
- **Where:**
  - Page windows are separate top-level windows with holes cut by `SetWindowRgn` (`app/engine-cef/src/lib.rs`, `update_page_window_region`, about lines 150–195). The holes are in the right places, but the UI underneath doesn't paint into them.
  - Two earlier "fix disappearing controls" commits (`a60e6eb`, `5fdd911`) didn't solve it.
- **Hypothesis (check first):** Chromium's native window occlusion tracking (`CalculateNativeWinOcclusion`) considers the main window, and so our UI browser, occluded or hidden, and stops producing frames.
  - Test by launching with `--disable-features=CalculateNativeWinOcclusion`.
  - Also try `--disable-backgrounding-occluded-windows` and `--disable-renderer-backgrounding`.
  - Log whether the UI's `document.visibilityState` becomes `hidden` when a page is shown.
- **Fix direction:**
  1. If the flags fix it, set them in the command-line setup of `engine-cef` with a comment explaining why.
  2. If not, move the floating UI (Helm, notch, popovers) into its own layered top-level window above the page windows. P0-04b already spiked this (`spike/p0-04-helm`, D-009 Proposed). That needs the owner's OK because it settles D-009.
- **Done when:** with a web page open, the Helm shows the address, all its buttons work, and the notch shows Shields plus working minimise, maximise and close. Logged on Windows with a screenshot.

### AUDIT-02: Links that open a new tab or window do nothing. Severity: critical. Confirmed live
- **What happens:** a `target=_blank` link and `window.open()` both do nothing (test page items 1 and 2). This also kills sign-in popups (OAuth) and the Trail's core idea, branches from an opener.
- **Where:**
  - `on_before_popup` in `engine-cef` cancels the native popup (returns `1`) and emits `Event::NewWindowRequested`.
  - The shell's `is_shell_event` and `dispatch_engine_event` (`app/shell/src/main.rs` about lines 1058–1180) don't handle it.
  - `ui/live.js` ignores the resulting `new-window` message.
- **Fix:**
  - Handle `NewWindowRequested` in the shell by creating a view with `opener = Some(opener)`.
  - Foreground tab: show it. Background tab: create it without showing.
  - Popups and windows: open as a tab for now. Real popup windows for OAuth (which need `window.opener`) may need the native popup; investigate and log the result.
  - Block popups that have no user gesture (EDGE_CASES §2).
- **Done when:** test page items 1 and 2 open new tabs that appear as children of the opener in the expanded rail. A popup without a user gesture is blocked.

### AUDIT-03: The UI rebuilds the whole window on every change. Severity: critical (root cause of several bugs). Confirmed in code and live
- **Where:** `renderShell()` in `ui/shell.js` (about line 151) calls `root.replaceChildren()` and rebuilds everything. `ui/live.js` calls it from about 21 places, for every engine message (title, URL, loading...).
- **Effects:**
  - Inputs lose focus and text. The History search box can't be typed into (live). Typing in the Helm can be wiped whenever any page event arrives.
  - **Every render sends `set-rail-width` to Rust** (`shell.js` about line 158). Rust then calls `set_bounds` and `persist_session()`, writing `session.json` to disk on every title or loading change.
  - The sky canvas is recreated each time (see AUDIT-04).
  - This is exactly the rule in `docs/HANDOVER.md` §4: never rebuild what can be updated in place.
- **Fix:**
  - Build the shell once.
  - Update regions in place: rail, Helm address, notch count, popovers, page panel. Key them by a signature, as in Odyssey's `dataset.sig`.
  - Send `set-rail-width` only when the width actually changes.
  - In Rust, debounce `persist_session` (for example, at most once a second, and on quit).
- **Done when:**
  - Typing in the Helm and in History search survives page events.
  - `session.json` is written at most about once per second while a page loads (log write counts).
  - Visual check still passes.

### AUDIT-04: Sky animation loops pile up. Severity: high. Confirmed in code
- **Where:** `ui/sky.js` `createSky()` starts a `requestAnimationFrame` loop and a `visibilitychange` listener. `renderShell` throws the old canvas away without stopping its loop.
- **Effect:** with Stars set to Drifting (the owner's current setting) or comets on, every render adds another loop on a detached canvas. CPU grows the longer the browser runs. That directly undercuts the resource goal (D-012).
- **Fix:** keep one sky instance for the window's lifetime. `createSky` returns a handle with `update(options)` and `destroy()`. After AUDIT-03 the sky should never be recreated.
- **Done when:** after 200 simulated state updates, exactly one rAF loop is running (count it in a test hook). Idle CPU in Still mode is under 1% and logged.

### AUDIT-05: Downloads are invisible. Severity: high. Confirmed live
- **What happens:** a 100 MB download finished with no ring in the Helm, no popover and no message at all.
- **Where:**
  - Rust sends `download-progress` (`bridge.rs` `ToUi::DownloadProgress`), but `ui/live.js` has no handler.
  - `state.downloads` is only ever set by `ui/fixtures.js`.
- **Fix:**
  - Handle `download-progress` in the UI: keep a downloads map keyed by id, drive the Helm ring and the popover, and show Open or Show in folder when done.
  - Make sure the popover is visible over a page (AUDIT-01 and AUDIT-06).
  - `download-control` must use one consistent id scheme. segdl keys by path, CEF by numeric id; check `segdl::control` against `engine.download_control`.
- **Done when:** a 200 MB+ download from `tools/audit/test.html` shows the ring and the popover with speed and "8 connections"; pause, resume and cancel work; Open works.

### AUDIT-06: UI overlays are hidden behind page windows. Severity: high. Likely (verify once AUDIT-01 is fixed)

### AUDIT-07: Find in page never works. Severity: high. Confirmed live and with a test
- **What:** Ctrl+F on a page shows no find bar and highlights nothing.
- **Cause 1 (proven):** `ui/pagebasics.js` (about lines 58 and 141) sends `match-case` and `clear-selection` with dashes. `FromUi` expects `match_case` and `clear_selection`, and the enum has `deny_unknown_fields`, so serde rejects the whole message: `unknown field 'match-case', expected one of 'view', 'text', 'forward', 'match_case', 'next'`.
- **Cause 2:** the find bar is drawn by the UI over the page area, so it's hidden (AUDIT-06).
- **Fix:**
  - Send snake_case fields.
  - Add a Rust test that parses exactly what the UI sends for **every** message type.
  - Better still, add a JS-side contract test generated from `bridge.rs`, so field-name drift fails CI.
- **Done when:** on `tools/audit/test.html`, Ctrl+F and typing "findme" highlights 3 matches; Esc clears them.

### AUDIT-08: Ctrl+L and F6 don't focus the Helm from a page. Severity: high. Confirmed live
- **What:** with focus in a page, Ctrl+L does nothing visible, and the typed text is lost.
- **Cause:** the page is a separate top-level window. The UI calls `input.focus()` (`ui/live.js` about line 80), but OS keyboard focus stays in the page window, and the engine has no way to move it.
- **Fix:**
  - Add `Engine::focus_ui()`: activate the main window and call `host.set_focus(1)` on the UI browser, then focus the input.
  - Also make F6 work without Ctrl (`engine-cef` `on_pre_key_event` only checks it with Ctrl).
- **Done when:** with focus in a page, Ctrl+L and F6 put the caret in the Helm with the URL selected; typing and Enter navigates.

### AUDIT-09: History is empty and its search is dead. Severity: high. Confirmed live
- **What:** after visiting 4 sites, `odyssey://history` showed no rows. The side panel shows the design's sample text ("Four pages, one branch..."). The search box doesn't accept typing.

- **Done when:** visited pages appear grouped by day with branches; search filters them; Forget and Clear this day work.

## Stage B: data safety and security

### AUDIT-10: Linux password vault is effectively plaintext. Severity: critical (security). Confirmed in code
- **Where:** `app/vault/src/lib.rs` (about lines 135–152). On non-Windows systems, "encryption" is a XOR with a fixed pattern. Anyone who can read `vault.json` can recover every password.
- **Fix:**
  - Use the Secret Service on Linux (the `keyring` crate, or libsecret), with a clear error when no keyring is available.
  - Never fall back to storing passwords in a reversible form.
  - The Passwords page text says "Windows DPAPI" on every OS; make it OS-specific.

### AUDIT-11: The vault can lose every password. Severity: critical (data loss). Confirmed in code
- **Where:** `vault/lib.rs`.
  - `save()` writes with `fs::write`, which isn't atomic.
  - `load()` returns an empty store on any parse error (`unwrap_or_default`). The next save then overwrites the file, so one crash mid-write or one corrupted byte deletes all passwords.
- **Fix:** write to a temp file and rename (as `save_settings_atomic` does). On a parse error, keep the file, rename it to `vault.json.corrupt-<time>`, refuse to save over it, and tell the user.
- **Done when:** unit tests cover a corrupted file (not overwritten, user told) and an interrupted write (the old file survives).

### AUDIT-12: Opening a download can run commands (Windows). Severity: critical (security). Confirmed in code
- **Where:**
  - `open_file()` in `app/shell/src/main.rs` (about line 1436) runs `cmd /C start "" <path>`.
  - `segdl::sanitize_filename` allows `& ^ % !` in names.
  - So a site can serve a file named for example `a&calc.exe&.txt`, and clicking Open runs it through cmd.
- **Fix:**
  - Use `ShellExecuteW` (or `explorer.exe <path>`) with no shell parsing.
  - Also refuse to "Open" executables without a confirmation (EDGE_CASES §4 external programs).
- **Done when:** a test proves a filename with `&` opens only that file.

### AUDIT-13: AI keys are lost, and aren't in the secure store. Severity: high. Confirmed in code
- **Where:**
  - `AiConfig.api_key` has `skip_serializing` (`app/ai/src/lib.rs` about line 28), so `ai.json` never stores it and the key is gone after a restart.
  - `AiSaveConfig` replaces the whole config (`main.rs` about line 888). Saving again without retyping the key wipes it.
  - D-014 requires the OS secure store.
- **Fix:**
  - Store keys and the Odysseus token in Windows Credential Manager or the Linux Secret Service (the `keyring` crate).
  - A save with no key keeps the existing one.
  - The UI only ever sees `has_key`.
- **Done when:** a key survives a restart and a re-save, and never appears in `ai.json` or in UI messages.

### AUDIT-14: Sleeping tabs overwrite their URL with about:blank. Severity: high (data loss). Confirmed in code
- **Where:** `engine-cef` `sleep()` loads `about:blank`. That fires `UrlChanged(about:blank)`, so the shell stores `tab_urls = about:blank` (`on_url_changed`).
- **Effects:**
  - The Helm shows `about:blank`.
  - `session.json` saves `about:blank`, so a sleeping tab is lost if the app quits.
  - Closing a sleeping tab records nothing.
  - The scroll position is lost.
- **Fix:**
  - Ignore URL and title events while a tab is sleeping, and keep the real URL and title in the shell.
  - Restore the scroll position on wake.
  - Consider CEF's real discard options (check the docs, mark anything unverified).
- **Done when:** a sleeping tab keeps its URL in the Helm and in the session, and wakes to the same page and scroll position.

### AUDIT-15: Tab sleeping ignores audio and form input. Severity: high. Confirmed in code
- **Where:**
  - The engine never emits `Event::AudioChanged` (`engine-cef` has no audio handler), so `has_audio` is always false.
  - `has_form_input` is never set outside tests.
  - Tabs with active downloads aren't exempt.
  - The timeout is hard-coded at 600 s (`main.rs` `schedule_sleep_timer`), with no setting.
- **Effect:** music in a background tab stops after 10 minutes, and unsaved form text is lost.
- **Fix:**
  - Implement the audio state (CEF audio handler or media state).
  - Detect forms with unsaved input via a small script in the page, reporting only a boolean through a safe channel. Pages have no bridge, so design this carefully; do not give pages IPC.
  - Exempt tabs with active downloads.
  - Add a setting.
- **Done when:** EDGE_CASES §9 checks pass and are logged.

### AUDIT-16: Ctrl+Shift+T reopens the oldest closed tab. Severity: medium. Confirmed in code
- **Where:** `relight_last_closed` uses `pop_back()`, but `close_tab` uses `push_front` (`main.rs` about lines 238 and 252).
- **Fix:** `pop_front()`. Add a test.

### AUDIT-17: Queued engine events run in reverse order. Severity: medium. Confirmed in code
- **Where:** `main.rs` (about line 1203) drains `pending_events` with `Vec::pop()`, which is last-in first-out. Events are also only drained after the next UI message.
- **Fix:** use a `VecDeque` with `pop_front()`, and drain after every event dispatch too.

### AUDIT-18: Session restore loads every tab at once and breaks internal pages. Severity: medium. Confirmed in code
- **Where:** `connect()` in `main.rs` (about line 1030) calls `create_view(tab.url)` for every saved tab.
  - That isn't lazy (EDGE_CASES §6: restore lazily).
  - It passes `odyssey://` URLs straight to CEF. `FromUi::Open` maps them to "", but restore doesn't.
  - Restored tabs aren't announced to the UI until `load-settings`.
- **Fix:** create restored tabs asleep, with the URL and title kept in the shell, and load each when first shown. Map `odyssey://` URLs to internal pages.

### AUDIT-32: Stars connect to the cursor (port from Odyssey). Severity: feature. Not built
- **What Odyssey does** (`C:\Projects\Odyssey\ui\fx.js`, copy the logic, not the file):
  - `pointermove` on the window stores the cursor position, plus a normalised `-1..1` value for parallax. `pointerleave` and window `blur` clear it.
  - Starfield (`drawStars`, about lines 129–165): every star with depth `z > 0.4` within 150 px of the cursor gets brighter (up to +0.6 alpha, fading with distance).
